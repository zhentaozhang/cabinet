# Cabinet 数据真实性与真实数据接入设计

## 目标

让 Cabinet 的用户、开发者和审核者能够分辨用户事实、系统事件、外部导入、模型生成、规则生成与模拟数据。真实用户工作区不注入演示业务历史；模型和工具失败不得被伪装为成功；真实输入和可追溯证据逐步成为复盘、记忆和决策的依据。

本文件是路线级设计，涵盖多个可独立验收的子项目。实现时按阶段逐个拆成实施计划；外部连接器不得在来源追踪和真实运行边界完成前启动。

## 当前基线与发现

当前仓库已经有 Better Auth、工作区 Setup、用户目标/任务/Check-in、Postgres 事件存储、任务审批与审计、可选 OpenAI 兼容模型调用，以及自动化测试数据库。

需要处理的现有真实性边界：

- `src/lib/db/seed.ts` 含演示用户及固定目标、任务、记忆、运行、复盘和指标数据。
- `src/server/services/commands/tasks/run.ts` 写入固定工具结果、步骤内容、Token 数和延迟；这些不是实际外部工具返回。
- `src/lib/llm.ts` 在模型未配置、异常或空响应时返回 `null`；`run.ts` 随后会用 `draftFor()` 模板产物继续流程。
- `src/server/services/shared/draft.ts` 含角色对应的固定研究、预算、练习、技能、风险和计划内容。
- `src/server/services/commands/council/positions.ts` 使用规则拼装立场；这不是多模型独立研究的记录。
- `src/server/services/commands/apprentice.ts` 的考试产物是确定性模拟。
- `src/lib/setup.ts` 自动写入固定预算、偏好、工作时段和精力模式。
- `src/lib/auth/context.ts` 在非强制认证模式中回落到 demo 用户。
- 演示账号登录、reset 控件和 seed 目前存在于应用代码中。
- README 对认证、Setup、测试数量和功能状态的部分说明已过期。

这些问题不意味着所有固定内容都应删除。Agent 角色/权限模板、状态机、验收机制、策略默认值、空状态提示和测试夹具是产品机制或测试设施，不应被误当成业务历史。

## 设计原则

1. **来源优先**：任何进入页面、指标、记忆或决策的业务信息都能说明来源、创建时间和可信状态。
2. **不以模拟冒充真实**：没有真实模型或工具结果时，不创建成功形态的真实运行记录。
3. **个人画像须确认**：默认建议不等同于用户事实；未采集的字段保持未设置。
4. **证据与结论分开**：模型输出是生成内容或建议，不能自动成为用户事实。
5. **失败显式化**：失败、超时、未配置和部分完成应以明确状态呈现，不能静默成功降级。
6. **最小授权**：外部连接器按需授权、优先只读，保留撤销和删除能力。
7. **测试隔离**：自动化夹具只进入独立测试数据库；演示 seed 只能显式用于隔离演示环境。

## 数据类别与处理规则

数据来源分类：

| 来源类别 | 定义 | 示例 |
|---|---|---|
| `user_input` | 用户主动填写或确认 | 目标、任务、约束、Check-in |
| `system_event` | 应用真实执行后记录的事件 | 审批、任务状态变化、审核、采纳、回滚 |
| `external_import` | 经用户授权从外部来源导入 | 文件、笔记、搜索结果、日历条目 |
| `model_generated` | 模型生成的内容 | 产物草稿、建议、会议立场 |
| `rule_generated` | 确定性规则推导的内容 | 规则型反思、政策判断 |
| `demo_fixture` | 演示或自动化测试样本 | seed 数据、测试工厂构造的记录 |

相关记录按适用场景保存 `sourceType`、`sourceRef`、创建时间、生成/导入模式、模型/provider 标识、运行状态和引用证据。凭证（API Key、OAuth token）不属于来源元数据，不得写入普通业务记录。

处理链路：

```text
用户输入 / 外部授权导入 / 真实系统事件
  → 输入校验、租户归属检查、来源记录
  → 真实工具或模型调用（若需要）
  → 保存产物、调用状态、引用证据和用量
  → 用户审核/确认（按动作风险决定）
  → 进入任务、记忆、复盘和指标
```

没有来源或证据的生成内容可以作为待审草稿展示，但不能作为已验证事实、真实外部操作完成结果或审计通过的依据。

## 模型与密钥管理

- MVP 由应用部署方统一管理模型 Key。
- 本地开发 Key 放在未提交的 `.env.local`；生产/测试部署放在平台服务端 Secret 管理。
- 只有服务端模型模块读取 Key；不向浏览器暴露、不在日志回显、不存入普通用户表。
- Key 未配置时，真实任务返回明确的“模型未配置”错误/状态，不自动替换为 demo 产物。
- 请求失败、超时或空响应时，运行标记为失败或部分失败，保存安全的错误类别和重试状态；禁止成功形态 fallback。
- 明确开启的演示模式可使用确定性模板，但所有 run/artifact 均标记为 `demo_fixture`/simulated，并与真实工作区隔离。
- 成功调用保存 provider、model、请求耗时、实际 Token 用量；费用只有在计价来源可信时标为实际值，否则标记为估算。
- 设置页只展示 Key 已配置/未配置、模型标识和最近健康状态，不显示 Key 内容。轮换由部署端完成。

## 工作区和演示数据

- 注册和正式 Setup 不写入示例目标、任务、运行、记忆、会议或周报。
- Setup 允许用户填写或确认 timezone、目标及个人约束。未提供的预算、偏好、精力时段保持空值/未设置，不填入看似真实的个人画像。
- 固定 Agent role、职责、权限模板可以作为产品默认结构保留；用户应能在创建时查看并确认。演示名称不应伪装为用户已自定义的人物信息。
- 生产环境拒绝 demo seed、demo login 和 destructive reset。
- 测试 fixture 仅用于每次测试运行独立的临时数据库；不能通过默认登录路径展示给真实用户。
- 显式 demo 环境可以保留 seed，但必须清楚标识模拟环境，且不能与正式用户数据共享数据库/租户。
- 没有目标、任务、记忆或指标样本时，页面展示空状态或“数据不足”，不插入示例业务内容填满页面。

## 工具、内阁和学徒的真实性

- 工具步骤仅在连接器实际执行后记录其结果；计划中的工具调用、未连接工具和模拟结果必须使用不同状态。
- 当前占位搜索/笔记/账本调用不得记作真实结果。连接器未接入时明确显示未连接或不可用。
- 内阁规则生成的发言标为规则生成；以后接模型生成时记录参与模型、输入证据和失败状态。不能声称各 Agent 独立研究，除非每个实际完成其调用。
- 学徒确定性考试保持为模拟评估，不能作为真实技能认证或能力增长证据。完整评估、灰度和回滚作为后续独立能力规划。
- 审批只代表授权，不等同于预订、支付等外部操作已执行。将来外部动作需单独记录请求、授权、实际调用结果和核验凭据。

## 真实数据接入顺序

1. **原生用户输入**：目标、任务、验收标准、约束、Check-in 和用户确认事实；先改善空状态、修改和删除路径。
2. **用户文件/笔记导入**：用户主动上传，记录文件来源、导入时间、解析状态和可访问范围。
3. **网页搜索**：Researcher 只在真实搜索连接器成功后记录结果；每个结论保留 URL、抓取时间和引用片段。
4. **只读日历**：用户明确授权后读取日程，用于规划；第一版不写入日历、不自动预订。
5. 后续连接器按用户价值、隐私影响和维护成本逐项立项，不在本路线中承诺支付或其他高风险写操作。

连接器必须支持未连接、已连接、同步中、失败和已撤销等状态；导入数据删除和撤销授权应有明确行为。连接器失败不能使用旧 demo 内容伪装成新鲜数据。

## 指标和展示

- 所有指标说明口径、时间范围、数据来源和是否估算。
- `demo_fixture` 不进入真实用户指标。
- 用户自报数据应标为自报；系统观测事件应标为系统记录；模型推断不计为已发生事实。
- 样本不足时显示“数据不足”或空值；不能用固定示例数填补。
- 允许估算的指标（例如管理时间）必须显示估算标记和计算方法，不能呈现为实测值。

## 实施阶段与独立验收

### 阶段 A：真实性清单与运行状态定义

建立覆盖 seed、固定工具步骤、模板产物、规则内阁、模拟学徒、默认画像、demo fallback 和演示登录的清单。定义真实、规则生成、模拟、失败、未配置、未连接的状态语义及页面标记。

**验收：**每个已知模拟点有明确 owner/显示策略；新增测试验证来源标签和状态语义；文档与代码当前行为一致。

### 阶段 B：阻止假成功

移除真实运行路径的模板 fallback；模型未配置或失败时显式失败。分开真实工具执行与占位步骤。模拟运行只能在显式 demo 环境中执行并使用独立标识。

**验收：**API Key 缺失、超时、异常、空结果均不能产生 `succeeded` 的真实 run 或成功 artifact；成功结果要求真实调用返回；demo 结果可被查询层和指标过滤。

### 阶段 C：来源追踪底座

确定 schema/DTO/API 的来源字段与状态表达，覆盖 run、artifact、memory、外部导入和指标来源。保持现有审计与租户边界。

**验收：**API DTO 能返回来源类别和必要引用；真实与 demo 数据可被查询和统计明确区分；迁移测试、双租户和导出删除测试通过。

### 阶段 D：真实工作区与数据采集

清理 Setup 的个人画像默认值，正式注册不创建样例业务历史；完善空状态、确认/编辑/删除和用户数据导出。演示 seed 与测试夹具物理/逻辑隔离。

**验收：**全新用户注册后没有虚构业务历史；用户未填写的画像字段保持未设置；生产不能运行 demo seed/reset；自动化测试使用独立临时数据库。

### 阶段 E：模型运行和费用可观测性

使用部署端 Secret 管理 Key，完善配置检查、模型错误状态、重试、用量字段、估算标记和设置页健康信息。

**验收：**密钥不进入 client bundle、API 响应、数据库业务行和日志；成功/失败/未配置路径均有测试；真实用量与估算成本不混淆。

### 阶段 F：真实输入连接器

依次实现文件导入、带引用的网页搜索、只读日历；每个连接器独立设计权限、数据保存、撤销、删除、失败和重试。

**验收：**连接器至少有成功、空数据、权限拒绝、超时/服务错误、撤销授权和删除数据测试；引用可回溯至原始来源；未连接时不产生伪造成功事件。

### 阶段 G：产品端到端验收和文档收口

验证“注册 → 真实输入 → 模型生成 → 用户验收 → 复盘/记忆 → 导出/删除”，并更新 README、数据来源说明、部署 Key 说明和 CI。

**验收：**端到端流程不依赖 demo seed；同时验证模型未配置/失败及双用户隔离；typecheck、lint、test、build、migration 全绿。

## 风险与不在当前范围

- **兼容性风险：**既有 demo 数据可能缺来源字段；迁移应给历史记录标为 `demo_fixture` 或 `legacy_unknown`，不能默认当作真实。
- **模型结果不确定性：**模型提供方可能不返回准确费用；此时只记录实际 token 和可追溯的费用估算。
- **隐私风险：**文件、笔记和日历需最小权限、来源可见、撤销和删除路径。
- **迁移风险：**当前工作区包含未提交代码和迁移，不应在该工作区直接混入真实性改造；实施前需选择并确认干净基线/隔离 worktree。
- 当前不实现：用户自带 Key（BYOK）、日历写操作、支付/预订、自动化高风险外部动作、完整技能认证、向量数据库迁移。

## 决策记录

- 用户确认正式用户环境不注入演示业务数据，自动化测试夹具继续隔离保留。
- 用户确认整体验证与数据接入应一次规划，但按独立阶段分批实施。
- 用户确认 MVP 由应用统一管理模型 API Key。
- 用户确认连接器按文件导入 → 网页搜索 → 只读日历的推荐顺序规划。
