# Cabinet 前端工作台优化设计

## 状态

设计已由用户确认。本文作为后续实现计划的依据，不代表功能已经实现。

## 目标

在保留 Cabinet 当前工作台定位、暗色视觉和治理能力的前提下，优化 Today 与任务详情两条核心体验，让用户能快速判断：

1. 现在需要我做什么？
2. 任务进行到了哪一步，是否受阻？
3. 哪些产物和来源是真实的，哪些仍需核验？
4. 我下一步需要批准、复核、重试还是继续等待？

设计借鉴 Cue 的“先呈现摘要、再展开细节”和 Muse 的“执行过程可见、关键动作需用户控制”，但不复制其品牌、对话主导交互、会议录音或云端浏览器能力。

## 产品方向与方案取舍

选择**渐进式工作台升级**：

- 保留现有侧栏、路由和 Cabinet 的深色 Obsidian 视觉。
- 首期覆盖 Today 和任务详情。
- 先优化现有任务/行动工作流，不新增全局对话入口、Inbox 或会议录音界面。
- 不进行 Cabinet、Memory、Council 的全站重塑。

未选方案：

- **对话优先**：当前没有完整对话与流式运行后端，容易让界面承诺超过实际能力。
- **全站全面重塑**：范围过大，会在核心任务旅程得到验证前制造视觉返工。

## 当前实现依据

- 全局样式已定义暗色设计 token、表面层级、文字角色和强调色，见 `src/app/globals.css`。
- 桌面侧栏和移动端抽屉已由 `src/components/shell/` 下的组件实现。
- Today 已有待处理决策、目标、指标和快速操作，见 `src/app/page.tsx`。
- 任务详情已展示任务状态、运行步骤、产物、证据、验收和操作，见 `src/app/tasks/[id]/page.tsx`。
- 前端通过 `src/lib/api/` 调用 API，并使用 `src/contracts/` DTO；该边界继续保持。
- 任务运行当前在 API 请求期间同步执行；首期不能展示并不存在的实时 worker 进度。

## 设计原则

### 保留既有识别度

延续暗色 Obsidian 基调、当前强调色、侧栏导航、卡片表面层级和字体 token。优化信息结构和可读性，不通过更换整套主题来掩盖层级问题。重要文本的对比度和字号优先于装饰性 eyebrow、边框和发光效果。

### 先行动，再解释

页面首先回答当前状态和下一步行动；预算、统计、治理依据作为上下文，不与用户当前需要处理的动作争夺视觉优先级。

### 过程透明，不伪造状态

演示、规则、模型生成和未知来源保持明确区分。只有数据层已有的状态、步骤和时间戳可以显示为已发生；不得用动画或模拟百分比制造实时进度假象。

### 错误可解释且可操作

加载、空状态、失败、部分成功、证据不足、人工待复核和审批中均有可读的专属状态。状态不只靠颜色传达。若用户可采取行动，状态说明应指向对应操作。

### 移动端与无障碍

维持当前移动端抽屉导航。主要 CTA、状态摘要、引用与验收说明在窄屏上仍可读可操作。交互支持键盘焦点，控件名称明确，状态不能仅由颜色编码。

## 页面设计

### Today：行动首页

建议的信息顺序：

1. **待处理与需要用户介入的事项**：待审批、待复核、失败或受阻任务；显示数量、原因与直达入口。
2. **下一步行动**：当前建议用户推进的任务或明确的创建任务入口。
3. **目标上下文**：主要目标和进度，解释任务与目标的关系。
4. **周度概览**：预算、学习、回忆等作为辅助指标，不挤占首要行动区。

零待办时保留稳定区块，并说明目前没有待处理事项；同时给出适当的创建或查看入口，避免让区块消失而产生数据是否加载成功的疑问。

Today 当前读模型的任务状态筛选不包含 `failed`。P1 必须在 `src/server/services/queries/today.ts` 扩展只读筛选，将失败任务纳入其 DTO 已有的 tasks 列表，再由页面显示。这里的“受阻”是 UI 对现有 `awaiting_approval`、`rejected` 或 `failed` 等持久化状态的分组/描述，不新增 `blocked` 领域状态，也不从客户端猜测服务端状态。实现前应确认哪些现有状态确实需要用户操作，并让 CTA 对应到已有路由和行为。

不把规则生成的早报、周报包装成模型洞察；如保留摘要，应显示其来源/生成方式，并使摘要不替代原始待办和状态。

### 任务详情：执行工作流

围绕任务从创建到完成的单一主线组织内容：

1. **任务身份与目标**：标题、描述、优先级、目标及执行/验收角色。
2. **当前状态摘要**：状态、最近一次运行、阻塞原因和可执行的下一步。
3. **执行与工具时间线**：只显示已持久化的步骤、真实连接器结果和错误语义；清楚区分未连接、未授权、跳过、失败和成功。
4. **产物**：正文优先可读，来源模式（模型、规则、演示、用户输入）在产物附近明确显示。
5. **证据**：来源类型、标题、URL、检索时间和引用关系；可区分已引用、未引用、悬空引用。证据存在不等于证据支持结论，页面文案不得暗示已验证事实。
6. **验收**：结构规则、证据要求和人工待复核分别呈现；清楚显示通过、失败、未判定。
7. **状态相关操作**：审批、复核、重试、继续等操作依当前状态出现，不把无效或互相冲突的操作同时平铺。

运行仍同步时显示数据库中已有的 queued/running/succeeded/failed 状态和已记录步骤，不做实时进度条或伪造的阶段动画。用户操作后可以沿用当前刷新行为。若后续运行机制提供事件流或轮询 API，再单独立项实现实时更新。

## 视觉与组件边界

- 继续以现有 `src/app/globals.css` token 为视觉基准；不新增互相竞争的颜色和字号体系。
- 将页面组合整理成小型、单职责展示区块，优先复用 `src/components/ui.tsx` 与现有 action components。
- 将可复用的派生文案/状态映射放在相应 `src/lib/presentation/` helper 中；不要在页面中复制领域规则。
- 业务状态只依据 API DTO；禁止从前端直接导入 server、数据库或 service 逻辑。
- 若 DTO 缺少支撑真实状态展示的字段，登记为后端依赖并通过契约扩展补齐；不得在 UI 中推断不存在的数据。

可能涉及的文件（实现前需重新核对当前分支和未提交改动）：

- `src/app/page.tsx`
- `src/app/tasks/[id]/page.tsx`
- `src/server/services/queries/today.ts`（P1 将失败任务加到只读查询结果）
- `src/server/readmodels/today.ts`（若新增派生字段，则保持 DTO 映射）
- `src/components/ui.tsx`
- `src/components/actions/`
- `src/lib/presentation/today-view.ts`
- `src/lib/presentation/task-view.tsx`
- `src/contracts/dto/`（只有 DTO 确实不足时）
- `tests/unit/`
- `tests/integration/page-contracts.test.ts`

## 实施顺序

### P0：任务详情信息层级

- 审查现有详情页内容和状态判断，先确定页面区块顺序和操作可见条件。
- 优先重组状态摘要、执行时间线、产物、证据、验收与操作区，不改变服务端状态机。
- 覆盖成功、失败、审批中、工具未连接/未授权、证据不足、演示/规则产物、人工待复核等状态。
- 给引用关联和未知状态提供可解释呈现。

### P1：Today 行动优先

- 将待审批、待复核、失败/受阻任务组织为行动队列。
- 在 Today 读模型中纳入失败任务；优先使用现有任务 DTO 字段，只有不能表达的必要数据才扩展聚合 DTO。
- “受阻”仅为 UI 分组，不新增数据库/领域状态；由后端返回的持久化状态决定分组。
- 令目标和周指标成为辅助上下文。
- 为无待办和无目标状态提供稳定空状态及适合的 CTA。
- 保留当前早报和指标行为，不改变其计算语义。

### P2：一致性与可访问性收口

- 统一相关页面的状态文案、状态色、CTA 层级、间距和移动端布局。
- 核对键盘导航、焦点状态、语义标签、文本对比和非颜色状态提示。
- 仅基于实现中出现的重复模式抽取共享展示组件，避免先建通用框架。

### 后续候选（非首期）

- 文件、会议材料或笔记输入 Inbox。
- 后台 worker 存在之后的实时运行进度与活动流。
- 对话优先交互、自动会议捕获、Cue 式转录页面。
- Cabinet、Memory、Council 的全站视觉重塑。

## 数据、错误和行为约束

- 页面只消费 API 返回的 DTO 和现有 presentation helpers。
- 不改变 mutation/API 写行为、业务权限、审批、预算或验收规则。允许对 Today 做向后兼容的只读读模型扩展（当前明确需要纳入 `failed` 任务）；若还需 DTO 字段，再做最小的契约扩展并增加契约测试。
- 模型、规则、演示和用户提交来源始终可区分。
- 失败、超时、未配置、部分成功、无证据和未知状态均不能伪装为成功。
- 页面不推断工具“运行过”，除非有持久化步骤或调用记录。
- 沿用当前 Idempotency-Key、错误码和刷新交互。

## 验收标准

1. 用户可以在 Today 第一屏识别待处理事项、受阻状态或“当前无待办”，并找到合适入口。
2. 用户可以在任务详情快速找到当前状态、最近执行结果、产物、来源/证据、验收结论和下一步操作。
3. 模型生成、规则生成、演示和用户输入不会被混淆。
4. 引用 ID 不存在、证据不适用或人工项未判定时，界面不显示成事实核验通过。
5. 无持久化运行进度时不显示实时进度或虚构阶段。
6. 桌面和窄屏布局可用，键盘用户能够定位和执行主要操作。
7. 现有路由、DTO 契约、权限行为、主要 CTA 和刷新行为不回归。
8. 相关 unit、页面契约/集成测试及项目既有 lint、typecheck 和 build 检查通过。

## 设计边界

首期不要求像 Cue 或 Muse 的品牌视觉，也不要求把页面改造成对话产品。完成标准是改善实际任务旅程的可读性、可信度和可操作性，而非新增视觉装饰或扩大页面数量。

实施时工作区可能包含其他未提交改动；实现者必须先审阅目标文件现状，只做增量整合，不得覆盖或回滚与本设计无关的改动。
